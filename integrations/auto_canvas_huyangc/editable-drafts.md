# 网页预算、完整结果与可编辑草稿

核对日期：2026-11-27，适配分支 `8a65a26`、算法基线 `2405d49`。本文只讲网页／`--result-policy editable`；离线默认完整模式调用主flow，其每候选120＋30＋30＋30秒与外层720秒不套用于网页。

## 网页执行顺序

```text
读取、准备原生项目
→ 正常运行候选2，保存合法结果或安全失败现场
→ 正常运行候选3，保存合法结果或安全失败现场
→ 任一正常结果完整合法：共享缩线、按原规则选图，不救援失败候选
→ 两份正常都失败：共享剩余时间，原候选修复 → 局部救援 → 1.5倍扩距
→ 首份完整恢复成功即结束；仍未完成则选择安全草稿
→ 原生导出、独立验收及原始版本事务复验
```

网页不进入候选1或bus，不拿历史合法成品给本次输入兜底。源码调用、失败现场与结果转换隔离在适配层，核心SA、A*代价和几何规则保持。

## 时间怎样分

后台总执行上限默认300秒，含输入、转换和原生验收，不含排队及浏览器传输。选多个Document时共用额度，不是每个Document或每个候选各300秒。提前完成立即返回。

算法子进程最多240秒，内部留6秒收尾；`candidate_schedule.py`的正常候选额度为 `min(120, (算法额度−6)/2) × 0.72`，满额时每个84.24秒，外部读取和剩余时间可进一步裁剪。两份正常都失败才使用剩余恢复额度：先分给修复三分之一，再给救援当时剩余的一半，最后扩距用余量。未用时间顺延，完整恢复成功立即停止。

安全缩线仍共用原5秒额度；源模型准备、转换、保存重读和原子事务使用外层预留，并受300秒总截止约束。超时只读取已经原子落盘的安全状态，不能读半个JSON或把半段A*尝试当作完整线路。

## 草稿必须满足什么

- 包含全部原电气器件的一份静态合法布局，保留身份、端口、主列和朝向规则。
- 位置、场景和已完成网络来自同一检查点，未完成分支不计作完成网络。
- 每个保留网络独立复验，所有真实引脚有安全固定出线；不合法网络的非固定线路不能保留。
- 允许缺线，不允许异网误接、穿体、器件遗漏、假连接或错误供电命名。
- 原生电气身份、供电连接、保存重读和最终事务验收继续执行。

完整结果优先于任何草稿。草稿先保结构，再比较真实已连接端子比例、已完成网络、剩余连接和现有线路。`resultKind: editable_draft`、`complete: false`、`geometryValid: true`明确表示“静态安全但没画完”，`draft_metrics`不冒充完整图指标。

网页warning／Details提示未完成数量，真实飞线保留，用户可以继续手工接线、保存或Undo。解析/资源错误、静态冲突或模块没放齐时不导出草稿。取消、切换项目或文档版本变化都会丢弃结果，不自动应用旧缓存。

## 可选附件预算

网页明确传 `--layout-budget adaptive`；离线适配CLI默认legacy，主CLI也不自动启用adaptive。通用接口的K复杂度档位、额外必要插入额度和共享恢复账本见[主算法说明](../../docs/passive-modules.md#可选的独立附件预算接口)。

adaptive解决的是额度耗尽时的必要补试，不保证能找到位置。当前核心还包含正常二维择优和失败二维续插，这是后续算法能力，不能把2026-11-25日志里的“本轮未增加找位”当作最新核心限制。

## 调用和排错

先从[WEB启动说明](WEB.md)进入适配检出目录。离线测试同一草稿策略时：

```powershell
Set-Location D:\gongzuo\.cache\worktrees\adapt-algorithm-sync
& D:\gongzuo\.venv\Scripts\python.exe -X utf8 -B `
  -m integrations.auto_canvas_huyangc `
  --project-root D:\auto-canvas-huyangc --engine-root . `
  --input <项目.icproj.json> --out-dir <新的空输出目录> `
  --result-policy editable --total-seconds 300 --layout-budget adaptive
```

`editable-engine-report.json`的`scheduling`记录实际正常额度、是否恢复及停止原因；版本为 `normal-2-3-then-shared-recovery-v1`。恢复耗时记全局阶段，不重复算到两个候选；`candidate-*-wire-plan.json`按候选分别原子保存。

旧300秒调度换序、C23草稿与完整结果、adaptive首次测试保留在[历史日志](history/editable-drafts-log.md)。其中BJT637的早期插入失败不代表当前主算法仍失败；目标符号、资源和网页预算不同，也不能把主线后来成功直接当作网页已验证。最新适配测试范围见[README](README.md#测试与实测)。
