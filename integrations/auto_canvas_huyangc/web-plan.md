# 原生网页规划接口 — 第二阶段

用户已授权执行网页适配。沿用 `adapt/auto-canvas-huyangc`；不修改第一阶段 plan.md。

## 范围与所有权

只修改 `integrations/auto_canvas_huyangc/` 的适配、测试和说明。算法源码、目标项目源码、锁文件保持原样。不调用 LLM，不安装或构建目标项目依赖，不切换目标仓库分支。

## 接入设计

1. 本机当前为 `.local/preview/web` 静态构建，按钮已有稳定 Worker 协议、项目会话／文档版本检查及一次撤销。独立适配主机提供原静态资源，以及实现该协议的 Python 远程规划 Worker。保留原生应用事务，不替换整个项目。
2. 静态资源通过带版本的虚拟命名空间加载，避免旧的 immutable／Service Worker 缓存使用旧规划 Worker。原静态目录不写入、不手改生成文件；原服务仍可单独启动。
3. 浏览器内存模型由目标项目自己的 validateProjectReadSnapshot / serializeProject 转成文件。后台使用第一阶段 CLI 运行原算法。原生标记修正的事务与初始 edits 合并后，再以一次原始版本事务复验；只有完整验收结果才返回浏览器。
4. 后台任务串行，队列有限；请求大小、可选单元、编辑数和时间受限。每任务独立目录。取消、页面离开、Worker 终止通过有限租约停止仅本次任务进程树，不能继续无限计算。不同标签页独立任务身份。
5. 本地 HTTP 只监听 loopback，校验 Host、Origin、同源凭据和输入；不能从客户端指定执行命令、资源目录或输出路径。端口、Python、算法根和预算只由启动配置确定。
6. 提供启动、停止和恢复原服务说明。先在独立端口测试，通过后以显式启动开关接替已确认身份的原 4173 静态主机；不终止未知程序，不自动刷新有未保存内容的网页。

## 验收

- 原 32 项适配测试继续通过；新增请求、队列、取消、租约、过期结果、原生合并事务和 HTTP 安全边界测试。
- Node 原生 test runner 验证 Worker 协议、进度、多单元结果、失败明确返回、没有偷偷使用旧算法。
- 使用当前部署构建，在浏览器中导入原生例子、点击原按钮，确认真实 Python 作业、线路返回；一次 Undo 恢复内容，Redo 恢复结果。验证取消和运行中编辑／切换后的版本保护。
- 关闭后可以用目标项目原启动脚本恢复原静态主机；算法／目标项目源码 Git diff 为空。
- 测试不调用外部付费 API；任务和浏览器进程只清理本轮自行启动的进程。

本阶段不扩展第一阶段器件、层次或总线支持，不重写网页布局／布线算法，不自动推送目标项目仓库。
