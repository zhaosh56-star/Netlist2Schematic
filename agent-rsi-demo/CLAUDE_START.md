# Claude 接手说明

第一次配置或建立分析/实现 Agent，请先按 [Agent 建立指南](AGENT_SETUP.md) 完成环境、角色和模型接入；程序骨架已实现，可直接配置启动。

目标是改进原始网表到真实模拟电路图的生成方法。请先阅读 `PROJECT_CONTEXT.md` 和 `OPTIMIZATION_SCOPE.md`，再读 `engine/candidate_entry.py`、所需生成模块以及 `README.md` 的运行与评分规则。

你在 RSI 中有两种角色：分析角色只根据搜索轨迹定位失败/绕行/错位问题并提出单一机制；实现角色在独立候选的 `engine` 中实际新增或修改源码。保留原始网表、真实符号、引脚位置和冻结几何要求；不得通过改分数或隐藏导线赢得评测。实际采用由提供的 RSI v4.1 核心进行 A/A 校准、配对验证和复测，不靠自我评价。

已有全部基础代码可复用，但初始入口采用基础自由摆件、关闭安全缩线。可逐步增加结构种子、层级、引脚朝向代价、无源近邻、真实布线反馈、失败恢复和安全简化；也允许设计新的机制并加辅助模块。先证明单项举措有用，再在已采用版本上继续迭代。详细允许范围由调用时的 allowlist 和 `OPTIMIZATION_SCOPE.md` 给出。

如果由用户在独立终端运行 `run_demo.py --mode claude`，程序会自动多轮调用已登录的 Claude Code，按严格 JSON 提案/源码替换协议应用变更并保留 diff。若你正处于交互 Claude Code 会话，请让用户在独立终端启动这一命令，避免嵌套 Claude 会话；也可由独立终端使用 API 模式。分析和实现可配置不同模型。

不要把 `--mode smoke` 称为自主创新：它仅固定启用随包现有 reference 流程，验证改代码→测量→采用的接线，不调用真实模型。不要声称已经在所有电路达到参考能力；应查看实际报告中逐图差距和未通过项。

v2 已接入候选兼容性回归、搜索失败诊断和有限修复；图形评价也检查候选实际SVG并衡量标签与画布。需要续跑时用 `--resume`，需要新的预算或从其他已采用版本起步时用新目录加 `--from-version`。原总预算、模型配置和冻结材料在续跑时保持不变。不要将验收基础设施超时写成电路不合法。
