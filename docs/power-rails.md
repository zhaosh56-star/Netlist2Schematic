GT中有两种常见画法：几个同排器件的供电端接到一条横线上，共用一个VDD标记；或者仍在各个器件旁保留独立标记。这个插件采用同样的局部原则，不要求整张图的所有VDD都合并。

## 怎么用

独立额外视图 `--power-rails` **默认关闭**。但默认正式图已经在内部调用同一类安全VDD合并，不需要加此开关；只关正式图中的合并用 `--formal-power-rails off`。下列开关用于在原有成品之外再生成独立共享VDD版：

```powershell
Set-Location D:\gongzuo
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir --power-rails auto
```

输出顺序是：原布局、SA、布线、恢复及安全缩线全部结束，原JSON和两种SVG保存成功，然后才运行插件。额外文件位于本次输出目录的 `power-rails/<输入与策略指纹>/`，包含彩色SVG、黑白SVG和记录JSON。插件失败不会影响原来的成功结果。

对已有合法JSON操作，可以完全跳过布局、A*和缩线：

```powershell
.\.venv\Scripts\python.exe -m netlist2schematic.plugins.power_rails.power_rails `
  --placement .\output\7\7-placement.json --out-dir .\output\power-rails\7

# 用上一步打印的JSON路径代替“共享记录.json”；只复验和重绘，不重新选位置
.\.venv\Scripts\python.exe -m netlist2schematic.plugins.power_rails.power_rails `
  --redraw 共享记录.json --out-dir .\output\power-rails\7-redraw
```

`--net-labels auto` 与这个开关可以一起使用，但分别基于完整成品生成两个独立展示版本，第一版不把两种展示变换叠在同一张图里。

## 哪些能合并

1. 必须是**同一个真实供电网**。AVDD与DVDD即使使用同一种符号，也绝不互连。
2. 第一版只处理VDD型标记、真实出线方向朝上、引脚高度相同的局部组，至少两个端子。地标记不变。
3. 使用当前物理行列间距的中位数S限制范围：相邻端子不超过3S，整组跨度不超过6S；最多检查连续八个端子的组合。没有物理坐标表的旧JSON按原网格恢复。
4. 先试整组，再给相邻小组处理机会。一部分引脚被阻挡，不妨碍另一部分安全合并。
5. 在引脚保护区外尝试少量水平轨道和标记位置。标记尽量居中；中点很靠近已有分接点时，优先重用该接点，避免挤出两个小圆点。

这些条件只依据网络身份、真实引脚、符号几何和相对位置，不读取GT坐标，不按图名、器件编号设置规则。

## 怎样保证不是“画一条假线”

插件先重新验收原来的完整线路，不能只信JSON中的旧 `valid=true`。然后才把选中的独立电源短线替换成真实的竖向接入线、共享横线，以及连到一个真实电源符号引脚的引线。器件位置、朝向、信号线路和网表均不变。

新符号的绘图原点由“真实接点减去几何表的引脚偏移”计算，避免把符号原点误当电气接点。

每个试案独立检查：

- 每个原始供电引脚都真实连到共享标记，既不能漏端子，也不能混入其他供电网。
- 引线只允许从自身引脚的真实出口穿过自身保护区；不能穿越其他器件。
- 新引线不穿越信号或其他电源引线，不新增交叉；新标记不能压在器件、信号线、其他标记或文字上。
- 共享横线、分接点与其他网络继续满足原有线距和节点净区规则。
- 共享网名与所属网络一致，新增文字不遮挡线路或已有文字。

普通主flow此前取消的“信号线不得经过旧电源标记保护矩形”规则没有恢复。这里额外检查的是**插件新建的标记和线路**，不改变原路由器的行为。

插件最多用5秒尝试128个轨道／标记组合；文字有三个附近备选位置。初始化复验、最终复验及写文件另有开销。不成功的试案完全撤销；超时交付此前已验证的合并，或者保持独立标记。不会为合并去移动器件、改信号线路、扩大布局或启动A*。

第一版不处理后备图等具有自定义 `power_connections` 的输入，会明确报告未处理并保留原成品。也不处理不同高度、侧向出线或需要穿越信号才能接成公共横线的组。

## 文件与指标

- `netlist2schematic/plugins/power_rails/rail_core.py`：通用分组、线路构造和独立几何／连接复验。
- `netlist2schematic/plugins/power_rails/power_rails.py`：保存结果读取、输入指纹、独立输出和重绘。
- `run_flow.py` 对应包内入口：只在原图成功保存后调用可选插件，默认绕过。
- `sa_render.py`：增加可选文字位置输入；原调用不传入时行为保持。
- `tools/compare_power_rails.py`：对保存结果生成GT／原图／共享版对照，不跑SA或A*。

共享记录内保留原布局和完整信号线路快照、根网表及include哈希、实际符号资源哈希、分组端子、真实标记接点、共享线路及文字位置。独立重绘重新验证依赖和几何；删线、错网、错标、悬空标记或输入变化会被拒绝。

原 `routes`、`metrics`、`quality.score` 和 `validation` 不被改写。共享版单独统计标记前后数量、合并组、实际供电线长、耗时和跳过原因；增加一条真实的共享横线通常会增加可见供电线长，不能宣传成信号布线优化。

额外SVG采用干净的文字标注，省去原分析图中的结构框和指标标题；比较器件和信号几何时应以实际坐标为准。
