# 可选auto安全缩线预算

`--simplify-seconds auto`只在显式选择时，根据保存线路的规模和工作量选择5、10、15、20或30秒的预算。普通命令仍默认5秒。它不改变布局、SA、A*、几何规则、接受条件或最多512候选的上限，也不增加简化调用次数。

报告中的 `budget_seconds`保存实际选出的数值，`budget_selection`保存auto选择依据、配置和特征。预算用尽、候选上限和自然收敛分别报告；选择30秒不代表一定会运行30秒，更不代表增加候选上限。

对已保存结果回放时，先独立验收线路。简化版本、auto估计器版本与配置、路由规则、上下文及输出线路指纹都匹配，才复用原先选定的预算和结果；不会对已经缩短的输出重新估计或继续累积优化。fixed与auto分别匹配缓存，显式切换策略时不能混用另一策略的缓存。新网表完整flow不走保存回放复用路径。

```powershell
# 默认仍为固定5秒
.\.venv\Scripts\python.exe .\run_flow.py .\examples\1.cir

# 显式选择auto预算
.\.venv\Scripts\python.exe .\run_flow.py .\examples\1.cir --simplify-seconds auto --out-dir .\output\1-auto

# 已保存结果只简化线路，位置不变
.\.venv\Scripts\python.exe .\run_flow.py --simplify-placement .\output\23\operational-amplifier-dut-placement.json --simplify-seconds auto --out-dir .\output\23-auto

# 仅发布已经执行完成的fixed5/auto记录，不运行任何优化
.\.venv\Scripts\python.exe -B .\tools\compare_auto_simplify.py
```

## 对照的起点必须说清楚

`output/auto-simplify-budget/`的fixed5与auto必须分别读取同一个输入JSON，不能先运行fixed5再把结果交给auto。两边复用相同布局和相同原线路，只有预算策略不同。

为了避免固定5秒命中输入文件之前的保存回放缓存，每个案例使用同一份冻结副本：只把旧的 `route_simplification`记录移到 `budget_comparison_input.previous_simplification`，原线路、位置和物理轴不变，也不修改原文件。移走缓存不等于撤销历史简化，已处理成品仍明确标为continued。执行记录保留 `original_source`以及共享冻结副本的哈希。

当前图1～7主图和图23已经进行过安全缩线，因此主组一律标记为 `continued`：是在现有成品上独立追加一次后处理，不是从头flow，也不冒充未简化路线。本轮新捕获的 `before_simplification`小型样例另列为原始起点，并保留证据。

只读探索发现，历史 `off-check`文件大多是已缩线成品的复制：关闭的是第二次缩线，先前的简化并不会被撤销，不能据此称其为原始布线。历史before目录中的图1、2、3、6没有安全缩线记录，且有routes、有效validation标记和匹配的源文件哈希；它们只能标为 `legacy_unrecorded`，无法仅凭字段缺失证明绝无历史处理。一个图6的无记录分析文件还带有手工改线证据，须排除。

## 验证与报告

所有实际计时串行执行，避免多进程竞争预算。发布工具只读取已保存记录和JSON，完全没有启动SA、A*、简化、重布或重绘的入口。原输入、现有成品与记录文件不被修改。

每对记录保留源JSON哈希、原始指标、最终指标、实际预算、实际耗时、停止原因、布局不变检查及auto选择特征。实际执行端负责独立完整连接与几何验收、双SVG同线、独立重绘和保存回放检查，发布端核对输出JSON与执行记录一致。

auto多花时间也不保证所有美观指标都改善；应同时看线长、交叉、折角和最终停止原因。若512候选先耗尽，仅延长时间可能不会改变结果。

## 当前规则怎样选档

当前版本为 `route-complexity-v1`，使用确定性规则估算工作量，不预测精确CPU耗时。首先合并纯共线切段，再统计以下指标：

| 指标 | 归一化基准 |
| --- | ---: |
| 不同网络的直线段配对数 | 2000 |
| 器件数量×规范化线段数量 | 2000 |
| 规范化线段数量 | 80 |
| 折角数量 | 40 |
| 分支点数量 | 15 |
| 至少三个端子的网络数量 | 8 |
| 长绕行链数量 | 4 |

长绕行链指长度比两端曼哈顿跨度至少多25%的链。另外计算“链多绕出的长度／总线长”，乘以2作为一个工作量分数。取这些分数和1的最大值，乘以最小5秒，再向上选择5、10、15、20、30秒中的一档；最大不超过30秒。没有折角、分支或多端连接机会的输入保留5秒。

特征提取最多0.5秒；若不能在此时间内完成，记录真实超时原因并保守分配30秒，不伪造特征。正常数字预算路径不启用估计器。报告里的实际缩线耗时不含特征提取和文件读写，估计耗时单独保存在 `budget_selection.estimation_seconds`。
