# 区域化布局：先组织功能区，再优化器件位置

本轮增加独立实验开关 `--region-layout auto|off`。开发阶段默认关闭；只有全部支持样例的最终出图、额外种子及视觉检查达到发布要求，才允许改为默认开启。

## 它改善什么

原算法主要知道“这几只管子相关”，但不同器件行可以各自排序，结果是上面属于左支路的管子到了下面又偏到右侧。区域计划在 SA 前记录功能区、局部支路、接入端口和附件归属，在各行使用一致的区域顺序。

首轮针对有完整连接证据的时控双支路核心、折叠主级和采样控制区域。识别依据是真实端口拓扑，不使用文件名、实例编号、信号网名或 GT 坐标。共用电源、偏置或时钟不能单独把器件合并成一个区域。

- 真正串联的器件优先对齐真实 D/S 或 C/E 引脚。
- 左右对应支路保持身份，但不同区域允许镜像和采用不同局部轴。
- 折叠、分叉与跨区反馈记录端口联系，不强制同列。
- 无源件仍可 flexible 跨行移动，附件归属采用软评分；大区域不是禁止其他器件进入的刚性矩形。

算法不要求导线镜像。A*、恢复链、网标开关及安全缩线继续沿用原实现。诊断叠加图上的框和虚线只是解释标记，不能当作实际导线。

## 接入和兼容

候选1保留原算法，候选2、3才尝试区域初排和区域动作。未识别到受支持区域时继续原路径。候选3不能用不兼容的旧布局反馈覆盖区域布局。

第一版 `--region-layout auto` 与 `--structure-layout auto`、`--symmetry-layout auto` 互斥。区域策略不会隐式开启旧结构实验或实验对称。固定布局重布、单独缩线及独立重绘不重新规划区域。

`layout_regions` 记录识别证据、归属、接口、覆盖率、初排及实际动作和指标。`applied` 表示新策略参与了布局，不代表最终选中了该候选，也不证明所有未识别支路都已经规整。原 `quality.score` 保留原含义。

## 使用

```powershell
# 单图尝试；输出到独立目录，避免覆盖原图
.\.venv\Scripts\python.exe .\run_flow.py .\test_data\11-15\strongarm-comparator.cir --cell dut --region-layout auto --out-dir .\output\region-layout-comparison\manual\strongarm

# 先跑两个重点样例；默认主种子及两个额外种子，off/auto 各运行一次
.\.venv\Scripts\python.exe .\tools\compare_region_layouts.py --cases data16 data24 --jobs 2

# 全部图1～7和GT输入；输出带指纹，重复执行可复验并续用相同版本结果
.\.venv\Scripts\python.exe .\tools\compare_region_layouts.py --jobs 2

# 也可先只跑关闭版，再以相同参数补开启版；另一侧仅复用同指纹结果
.\.venv\Scripts\python.exe .\tools\compare_region_layouts.py --policies off --jobs 2
.\.venv\Scripts\python.exe .\tools\compare_region_layouts.py --policies auto --jobs 2

# 只检查一个种子，取消重点样例的额外种子；用于开发，不替代完整验收
.\.venv\Scripts\python.exe .\tools\compare_region_layouts.py --cases data16 --seeds 20261029 --core-seeds --out-dir .\output\region-layout-comparison\probe
```

对照工具默认 20,000 次提案、正常预算300秒，局部救援/扩距/总线各60秒，缩线5秒。两个侧采用相同参数、完整导线和成品展示，不开启网标。GT仅作为视觉参考，不作为同规则下的线长最优解。

图6、7的对照沿用此前保存的规范输入及 provenance 文件，并在记录中明确路径和哈希；工具不会修改或补写原网表。当前不支持的输入明确记为跳过，资源错误和运行失败不能伪装成跳过。

## 如何查看结果和判定发布

`output/region-layout-comparison/index.html` 显示 GT／关闭版／开启版。每份结果链接完整 JSON、彩色图及独立区域/支路叠加图。`comparison.json` 保留逐网绕行、区域覆盖和未覆盖器件、实际候选、恢复阶段及耗时；`runs/` 内按案例、种子、策略和输入/代码/参数指纹隔离。

每份成功图独立复验原始引脚、固定出线、同网连通、异网分离和几何规则，并比较两种 SVG 的导线及独立重绘。两个侧依据同一份源网表计划重新测量，不能通过少识别关系获得更低的违规数。

发布门槛检查安全缩线后的最终成品：逐图线长不超过关闭版115%；原零交叉保持零，其余单图最多增加1处；验证集总交叉不增加；不新增失败、错误有源行变动或总线降级。重点样例还需要确认功能区和上下支路在视觉上确实更清楚。

工具不会自动修改默认值，也不会把部分案例的数值通过记作全量发布成功。自动批跑结束时，`default_promotion_approved` 为 false，视觉复核状态为 pending；实际看图之后再单独记录审查结果。本轮已完成7组看图，结论见下文。

## 代码与兼容验证

| 文件 | 职责 |
| --- | --- |
| `region_layout.py` | 根据拓扑建立区域、最低层归属、支路和端口关系；测量实际布局；按区域收益及原布线护栏选候选 |
| `region_placement.py` | 区域初排、真实串联引脚评分、区域平移／子区交换／支路换列／整体镜像；不运行A* |
| `structured_placement.py` | 候选1保持原行为，候选2、3按证据接入区域布局，保留flexible无源动作 |
| `aesthetic_flow.py` | 限制候选3反馈来源，布线后统一测量、选择，保留失败现场 |
| `run_flow.py` | CLI开关与互斥检查、保存元数据；恢复、重布和简化后只重测实际坐标 |
| `tools/compare_region_layouts.py` | 冻结输入与运行参数，完整出图、独立复验、生成带区域标注的对照 |

完整主项目测试为927项通过。另对修改前快照运行29份可解析输入、每份3个候选的120次提案检查：87份关闭版候选的位置、朝向、物理轴、能量和随机数状态均与修改前一致；29份参照候选也一致。这是状态兼容证据，不代替下文真实布线验证，也不承诺触碰墙钟截止时间时候选完成数量恒定。

网表、GT、符号资源和RSI文件保持原样；A*、几何规则、恢复链与缩线实现没有改动。审查记录见[测试](../output/region-layout-comparison/audits/unit-tests.json)、[旧状态兼容](../output/region-layout-comparison/audits/compatibility.json)及[文件保护](../output/region-layout-comparison/audits/protected-files.json)。

## 本轮完整实测：已有组织收益，仍保持默认关闭

正式批次使用32个输入（图1～7及25份GT网表），主种子20261029；StrongARM与OTA＋CMFB分别补20261030、20261031。共72次off/auto运行，采用上述默认迭代数、预算及sequential候选策略，`jobs=6`。并行数影响墙钟预算下候选能否及时完成，不能直接与其他并行度的历史耗时比较。

- 66份结果通过完整连接、几何、固定出线、双SVG同线及独立重绘；原有3份不支持输入在两侧共跳过6次，运行失败0次。
- 33组有效对照中31组通过逐图量化门槛，2组未通过。总线长146709→146846，总交叉155→156，折角838→834；总交叉不增加门槛未通过。
- 主种子的29组有效对照有28组过逐图门槛，交叉117→121。额外种子20261030有1/2组通过，20261031有2/2组通过。
- 两侧均为25份正常结果、7份局部救援、1份总线后备，没有新增失败或总线降级。输入及运行代码指纹检查通过。

以下数值均为安全缩线后的最终成品，依次为线长／交叉／折角：

| 案例与种子 | off → auto | 实际采用情况与结论 |
| --- | --- | --- |
| 图2，20261029 | 4044／11／19 → 相同 | 新候选执行，最后仍选原候选1；不能记作美观收益 |
| StrongARM，20261029 | 4084／5／19 → 相同 | 新候选2、3可布通，但实际线路成本超限，保留原候选1 |
| StrongARM，20261030 | 3600／6／12 → 4358／3／19 | 正常阶段选择区域候选2；穿插4→0、顺序冲突9→0，但最终线长增加21.06%，未过115%门槛 |
| StrongARM，20261031 | 4084／5／19 → 相同 | 保留原候选1 |
| OTA＋CMFB，20261029 | 7314／11／45 → 7153／15／39 | 两侧正常候选1、2均未成功，保留各自候选2布局后由局部救援接通；区域版顺序冲突44→0，但交叉增加4处，未过门槛 |
| OTA＋CMFB，20261030 | 7098／12／52 → 相同 | 正常预算只执行候选1，之后局部救援；区域候选没有执行 |
| OTA＋CMFB，20261031 | 6990／15／67 → 相同 | 正常预算只执行候选1，之后局部救援；区域候选没有执行 |

OTA主种子的区域初排确实采用，归一化真实引脚误差16.867→2.5，区域分散1.993→1.329。它是“区域布局＋原局部救援”的结果，不能描述为正常候选质量选优获胜。两组未通过门槛的原因也不同：StrongARM是最终缩线后相对关闭版超过线长上限；OTA是恢复结果的实际交叉数超限。运行时对已完成正常候选的筛选，不等于最终成品相对独立off运行的发布保证。

**当前识别的实际覆盖只有三个输入：图2、data16、data24。** 其他折叠电路若没有完整高置信证据，会保留旧路径；本轮没有实现所有折叠电路的整体重排。大多数相同成品证明兼容性，不能计为区域策略的美观收益。两份OTA额外种子没有执行增强候选，也不能当作增强算法的跨种子成功证明。

data25另有一处必须单独解释的差异：off为3530／1／23，auto为3070／1／18，但它没有受支持区域，区域策略没有介入。两侧候选1、2的原布线指标相同；off开始候选3时只剩0.778秒而超时，auto剩3.680秒、候选3用1.830秒完成。因此胜者分别为1和3。这是并发运行中的截止时机差异，不是区域算法缩短了导线，不能计入新策略收益。

本轮保持 `--region-layout off` 默认值。区域组织已经有可见改善，但尚未同时满足最终线长、交叉和跨种子覆盖的发布条件，没有通过放宽护栏使其默认开启。
