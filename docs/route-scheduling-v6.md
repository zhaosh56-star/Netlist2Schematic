# 安全缩线 v6：让长绕线优先获得处理机会

这次改动发生在完整布线通过验收之后，只调整导线简化的调度和候选排序。器件位置、网表、SA、A*、几何规则及恢复链保持原样。结构增强和实验对称模块仍默认关闭。

## 原因与处理

图23原先的5秒缩线预算全部消耗在直线／L形替换上。虽然已经去掉部分小折角，支线重接、三段折线和轨道内收仍然一次也没有执行。单纯加时还可能先碰到512个候选上限。

v6保留四类操作的先后顺序，但为后面操作保留累计配额。初始线路复验之后的剩余时间，按25%、50%、75%、100%设置阶段截止点；候选累计上限依次为128、256、384、512。前阶段自然收敛或达到自己的配额，都会进入下一阶段。未用完的时间和名额留给后面。

新阶段先尝试新启用的操作，再与前面已启用的操作轮转。每次接受后都重新读取最新已验收线路，后续操作不会恢复旧快照，也不能覆盖已经取得的收益。阶段截止中断中的试案不会被提交，最后始终保留完整验收通过的结果。初始复验已经耗尽预算时，报告明确记录后续未执行，不把阶段激活当作完成。

候选路径优先按“现有长度减去两端曼哈顿距离”排序，其次比较长度和折角，再以坐标和网名稳定排序。所有合格路径仍可处理，不存在图号、器件编号或网络名称特例。绕行余量用于排序，不代表这些长度全部能够安全删掉。

接受条件保持不变：原始引脚连接、固定出线、同网连通、异网分离和完整几何检查通过；总线长、总交叉、总折角都不增加，且线长或折角至少一项减少。

## 使用方式

常规flow使用原来的 `--simplify-routes safe` 默认值，仍使用5秒、最多512个候选。`--simplify-routes off`关闭该步骤；`--simplify-seconds`仍可显式调整时间。本次没有新增命令行参数。

保存结果的简化版本升级为v6。旧JSON仍可读取、验收和独立重绘；主动简化v5或更早结果时，不会因旧缓存而跳过新算法。同版本、相同参数和相同几何的保存回放继续保持稳定。

```powershell
# 只简化保存线路，跳过SA、A*和恢复链，并使用独立输出目录
.\.venv\Scripts\python.exe .\run_flow.py --simplify-placement .\output\7\7-placement.json --out-dir .\output\7-v6

# 图1～7和图23：继续处理现有成品并进行独立验收
.\.venv\Scripts\python.exe -B .\tools\compare_route_scheduling.py

# 仅验证图23
.\.venv\Scripts\python.exe -B .\tools\compare_route_scheduling.py --cases data23 --out-dir .\output\route-scheduling-v6\data23-check
```

## 对照的含义

对照入口为 `output/route-scheduling-v6/index.html`，完整记录在同目录的 `comparison.json`。图1～3的保存来源为v3，图4～7为v4，图23为v5。工具是在这些已验收的历史成品上继续后处理，不能把它当作“同一份未简化线路分别运行v5和v6”的公平比较，也不能把全部改善归因于调度变化。

每份成功结果均独立检查原引脚连接、固定出线、几何规则、最终指标、彩色和黑白SVG同线、独立重绘一致、关闭简化不改线、同版本重复回放稳定，以及原始输入和主图字节不变。工具通过补丁禁止SA、A*和恢复链被意外调用。

报告分别列出每类操作的实际尝试和接受次数、逐阶段截止及停止原因，以及逐网线长、端点包围盒外线长和绕行倍数。图23的 `iref` 和 `net9` 另列重点记录。多端树的线长自然可能大于端点包围盒半周长，该比值仅供筛查，不代表所有外围线路都能删除。
