# 默认只自动运行候选2、3，失败后修复原骨架

**当前默认（2026-11-23）：每张图一次120秒总时限，正常候选、失败恢复、安全缩线与正式输出共用；完成就结束。** 正常阶段默认上限95秒，局部救援默认上限15秒；扩距和总线只使用剩余总时间，不额外增加60秒。候选仍只自动尝试2、3。默认生成顶层 `*-formal.svg`（就近标号、GT风格字体、无白圈/虚框、合法局部VDD合并），`flow-result.json` 指向本次正式成品。`--time-seconds 240` 可提高总上限，`--formal-output off` 可关闭正式收尾。下文历史实验的300秒与独立60秒记录保留当时口径，不代表当前默认预算。

自本轮起，普通的新网表命令默认使用有源骨架优先的无源模块布局。无需添加开关：

```powershell
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir
```

## 一次运行怎样选图

```text
解析、识别和分层
→ 候选2：较宽松的有源骨架起点 → 无源模块插入 → A*和完整验收
→ 候选3：较紧凑的有源骨架起点 → 无源模块插入 → A*和完整验收
→ 有合法结果：对这些结果共用一次缩线预算，再选出成品
→ 两份都失败：使用剩余正常预算修复候选2／3，不重新运行SA
→ 修复通过：交付第一份完整合法结果
→ 仍失败：继续既有的独立局部救援、扩距、总线后备链
```

候选2、3使用相同的通用模块算法，初始顺序、节距和独立随机种子不同。它们都保护MOS/BJT主列，然后把具有真实端口的串联、并联、嵌套串并联附件作为模块插入。内部显示间隔可以扩大，符号尺寸及电气连接不变。构造细节见[无源模块说明](passive-modules.md)。

候选1不再自动初始化或参与恢复，仅保留`--candidate-id 1`显式回放。只要候选2、3中有一份完成完整验收，就不进入新增的失败修复。插入失败、静态检查失败、寻路失败和候选超时，都算该候选未完成；解析错误或损坏资源仍明确报错。没有适用的无源模块时，候选2、3继续使用原结构化路径及默认主列规整，不凭空生成模块。

## 从两份合法结果中怎样挑选

先对所有合法候选使用同一套安全缩线，比较最终实际线路。默认共用5秒、最多512个缩线试案；没有把每份分别加上5秒、512案。前一份未用完的额度留给后一份。选中后输出复验已有结果，不再给胜者重复收费。

通过完整连接与几何验收的候选，严格按 **折角数 → 交叉数 → 信号线长** 升序选择。只有前一项相同才比较下一项；三项完全相同按候选编号稳定决定。

旧的115%线长、零交叉保持及最多增加1处交叉门槛不再用于最终候选筛选。折角更少的合法图可以在线长、交叉更多时胜出；折角相同则优先少交叉。这是明确的排序，不是加权打分。

主列保护、子结构归属和无源模块规整继续用于布局，相关指标及原Q分数仍计算、保存，用于诊断和原有布局反馈。它们不能改变最后的排序；旧布局偏好建议记录在 `quality.layout_preference_diagnostics`，标记 `used_for_selection: false`。算法不读取GT坐标，也不按实例名或网名设置选图例外。详见[最终选图规则](candidate-selection.md)。

## 时间不会无限增加

正常阶段仍共用 `--quality-seconds 300`，含候选生成、SA、静态检查和最终A*。截止点按正常阶段开始时间累计计算：

| 候选 | 累计截止点 | 默认300秒对应时刻 |
| --- | ---: | ---: |
| 2 | 40% | 第120秒 |
| 3 | 80% | 第240秒 |
| 原主候选修复，仅两份失败时 | 100% | 最迟第300秒 |

提前完成的时间可以顺延；只要已有合法结果，剩余修复时间不花掉。两个正常候选的初排、SA随机流、40%／80%时限、缩线和排序保持。全部失败才进入`primary_repair`：恢复当次运行的实际骨架和独立检查点，尝试模块续插、已有局部接口／模块换通道，再尝试1.25倍物理间隔；不移动显式固定器件，不重新运行SA，不给每次尝试重置300秒。`--candidate-budget` 的旧 sequential／reserved 规则仍用于显式关闭模块的旧路径；新默认的有效策略记录为 `primary_reserved`。

正常阶段之后的恢复预算保持原值。缩线仍是独立共享预算；使用 `--simplify-seconds auto` 时，按本轮合法候选估计值的最大值选择一个5～30秒总额度，再分给候选。每个候选的原约6666步SA提案、12秒局部上限、原A*代价和几何规则保持。

### 全部正常尝试失败后的现场选择

默认2→3顺序分别保存真实的失败现场。实际进入路由的候选可保留独立检查点；模块插入失败时另以私有回调保存当次骨架，正常阶段两份都失败后才允许续插。没有完成静态检查的半成品不能用于路由或冒充成功图。候选1不能覆盖恢复对象。每份现场的布局、朝向、路由参数和已完成网络一起深拷贝，互不混用，也不把执行对象写入JSON。

仍然只使用一份 `--rescue-seconds` 总预算（默认60秒）。默认只尝试候选2／3；按已完成网络覆盖的端子比例、网络比例排序，同分时先试较新的现场。未完成的失败分支不算已完成进度。每次尝试按“总剩余时间÷剩余现场数”分配时间，未用完的时间顺延；找到第一份通过完整验收的结果就停止。此排序只是安排机会，不保证进度更多的现场一定能布通。

救援失败会撤销该次临时状态，继续下一个现场；全部失败才进入原扩距和总线链。扩距选择实际保存的主候选上下文，优先已完成端子覆盖较多的现场；未提交的救援试案不能覆盖它，也不会改回候选1。正常阶段有任何成功结果时完全不执行这项调度；显式候选回放、旧路径和固定布局重布仍保持原单现场行为。

JSON的 `local_rescue.candidate_recovery`（失败时在恢复阶段诊断中）记录版本 `candidate-checkpoints-v1`、尝试顺序、完成进度、时间分配、失败原因和选中候选。保存的 `routes`、质量分数及完整验收含义不变。

## 兼容与复现

```powershell
# 显式关闭模块，恢复原候选1→2→3生成顺序；最终仍按折角、交叉、线长排序
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir --passive-skeleton off

# 只回放一个候选；候选1也可按同样方式显式回放
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir --candidate-id 3
```

新增`primary_repair`记录版本`primary-failure-recovery-v1`、原候选、剩余正常预算、各项修复动作及失败原因。执行对象和续插回调只保存在私有异常属性，不写入JSON。输入、资源或源文件变化错误不进入恢复。

默认推广仅适用于新网表的 `layered + structured + flexible`。baseline、legacy、固定无源行及其他显式布局实验继续各自原路径，不隐式叠加模块。保存JSON的重布、单独缩线、独立重绘保持保存位置。显式请求不兼容的模块开关仍报错。RSI冻结引擎不变。

JSON 的 `quality` 记录计划顺序 `candidate_order`、实际 `candidates`、`reference_fallback_only`、`reference_fallback_used`、有效预算及共享缩线账本。候选记录中 `routing_metrics` 是缩线前，`metrics` 是本次用于比较的缩线后结果；`quality.score` 保持原综合质量含义，但不参与最终选图。正常选图的`quality.selection_policy`为`bends-crossings-wirelength-v1`；全部失败后的修复为`first_verified_primary_repair`，`routing_selection` 保存实际排序与各候选指标；显式编号回放仍为 `explicit_candidate_replay`。
