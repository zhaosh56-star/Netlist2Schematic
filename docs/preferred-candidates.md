# 默认先选候选2、3，候选1只作失败兜底

自本轮起，普通的新网表命令默认使用有源骨架优先的无源模块布局。无需添加开关：

```powershell
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir
```

## 一次运行怎样选图

```text
解析、识别和分层
→ 候选2：较宽松的有源骨架起点 → 无源模块插入 → A*和完整验收
→ 候选3：较紧凑的有源骨架起点 → 无源模块插入 → A*和完整验收
→ 有合法结果：对这些结果共用一次缩线预算，再选出成品
→ 两份都失败：才初始化候选1，运行原结构化布局和布线
→ 候选1也失败：局部救援、有限扩距、保持布局的网标恢复；不生成总线
```

候选2、3使用相同的通用模块算法，初始顺序、节距和独立随机种子不同。它们都保护MOS/BJT主列，然后把具有真实端口的串联、并联、嵌套串并联附件作为模块插入。内部显示间隔可以扩大，符号尺寸及电气连接不变。构造细节见[无源模块说明](passive-modules.md)。

候选1不参与正常竞争。只要候选2、3中有一份完成完整验收，就连候选1的初始化和SA也不会执行。插入失败、静态检查失败、寻路失败和候选超时，都算该候选未完成；解析错误或损坏资源仍明确报错。没有适用的无源模块时，候选2、3继续使用原结构化路径及默认主列规整，不凭空生成模块。

## 从两份合法结果中怎样挑选

先对所有合法候选使用同一套安全缩线，比较最终实际线路。默认共用5秒、最多512个缩线试案；没有把每份分别加上5秒、512案。前一份未用完的额度留给后一份。选中后输出复验已有结果，不再给胜者重复收费。

候选筛选仍保留防止线路严重退步的护栏：以本轮候选2／3中原综合质量最好的合法结果为参考，线长不超过其115%；参考零交叉时仍为零，其余最多增加1处。这些限制不再针对旧候选1或历史图。

在护栏内，优先保持主列连续、支路左右顺序和无关器件不侵入，再比较附件的方向、串并联形状、接入距离，最后比较原综合质量。**折角作为综合评分的软代价，不再仅因多一两个折角就否定结构改善。** 没有可靠组织关系时，仍由实际线长、交叉、折角、绕行等综合质量择优。电气和几何安全始终是硬要求。

算法不读取GT坐标，不按文件名、实例编号或网名选图。结构组织指标是可读性的近似；不能代替人工审美检查。

## 时间不会无限增加

正常阶段仍共用 `--quality-seconds 300`，含候选生成、SA、静态检查和最终A*。截止点按正常阶段开始时间累计计算：

| 候选 | 累计截止点 | 默认300秒对应时刻 |
| --- | ---: | ---: |
| 2 | 40% | 第120秒 |
| 3 | 80% | 第240秒 |
| 1，仅两份失败时 | 100% | 第300秒 |

提前完成的时间可以顺延；两份成功时剩余兜底时间不强制花完。候选1不重新获得300秒。`--candidate-budget` 的旧 sequential／reserved 规则仍用于显式关闭模块的旧路径；新默认的有效策略记录为 `primary_reserved`。

正常阶段之后的恢复预算保持原值。缩线仍是独立共享预算；使用 `--simplify-seconds auto` 时，按本轮合法候选估计值的最大值选择一个5～30秒总额度，再分给候选。每个候选的原约6666步SA提案、12秒局部上限、原A*代价和几何规则保持。

### 全部正常尝试失败后的现场选择

默认2→3→1顺序分别保存实际进入路由、且带有效检查点的失败现场。候选1不会覆盖候选2、3；插入失败、静态端口冲突或没有检查点的尝试不能提供救援现场。每份现场的布局、朝向、路由参数和已完成网络一起深拷贝，互不混用，也不把执行对象写入JSON。

仍然只使用一份 `--rescue-seconds` 总预算（默认60秒）。先尝试候选2／3，再考虑候选1；同组按已完成网络覆盖的端子比例、网络比例排序，同分时先试较新的现场。未完成的失败分支不算已完成进度。每次尝试按“总剩余时间÷剩余现场数”分配时间，未用完的时间顺延；找到第一份通过完整验收的结果就停止。此排序只是安排机会，不保证进度更多的现场一定能布通。

救援失败会撤销该次临时状态，继续下一个现场；全部失败才进入扩距和网标恢复。两档扩距共用原60秒，网标恢复使用原最后恢复阶段的60秒。它只读取当次生成的候选和现场，保持器件身份、行列及朝向，不重排成总线。正常阶段有任何成功结果时完全不执行恢复；显式候选回放默认关闭恢复，固定布局重布不扩大间距。

JSON的 `local_rescue.candidate_recovery`（失败时在恢复阶段诊断中）记录版本 `candidate-checkpoints-v1`、尝试顺序、完成进度、时间分配、失败原因和选中候选。保存的 `routes`、质量分数及完整验收含义不变。

以上完整线路的含义适用于正常出图、局部救援和扩距成功结果。最后的网标恢复另用 `route_representation: wires_and_labels` 与独立连接验收，`quality.score` 为null；其可见线长不与完整线路评分混用。详细说明见[无总线恢复](no-bus-recovery.md)。

## 兼容与复现

```powershell
# 显式关闭模块，恢复原候选1→2→3及原选图策略
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir --passive-skeleton off

# 只回放一个新候选，跳过另外两份和恢复链
.\.venv\Scripts\python.exe .\run_flow.py .\examples\7.cir --candidate-id 3
```

默认推广仅适用于新网表的 `layered + structured + flexible`。baseline、legacy、固定无源行及其他显式布局实验继续各自原路径，不隐式叠加模块。保存JSON的重布、单独缩线、独立重绘保持保存位置。显式请求不兼容的模块开关仍报错。RSI冻结引擎不变。

JSON 的 `quality` 记录计划顺序 `candidate_order`、实际 `candidates`、`reference_fallback_only`、`reference_fallback_used`、有效预算及共享缩线账本。候选记录中 `routing_metrics` 是缩线前，`metrics` 是本次用于比较的缩线后结果；`quality.score` 保持原综合质量含义。模块构造版本仍是v3，新的选择策略版本为 `active-first-primary-selection-v1`。

核心代码：`flow/aesthetic_flow.py` 调度及共用缩线，`flow/candidate_budget.py` 分配截止点，`layout/structured_placement.py` 按稳定编号惰性生成，`plugins/passive_skeleton/selection.py` 比较主列和附件，`flow/run_flow.py` 解析默认值并复验输出。`postprocess/simplify_routes.py` 只新增向下限制候选名额的参数，默认原算法不变。

本轮验证页在 `output/preferred-candidates-flow/index.html`；代码回归记录在同目录 `tests.json`、`tests.log`。该页只实测C33、C35、C44，不冒充全数据集的重新视觉验收。
