# 候选交叉净区预筛v8

v8在最终安全缩线中，让四类候选共用交叉净区预筛。候选线路如果已经能确认违反原来的交叉净区规则，就提前拒绝，避免占用完整验收的时间；其余候选仍交给独立完整验收。这一步不降低净距，不把预筛通过当成整图成功。

当前关注的是用户正在查看的v7图23成品继续处理：线长10489→9953，交叉保持12，折角77→76，IREF顶部轨道y=-260收至2。[对照页](../output/candidate-clearance-v8/index.html)优先展示这份结果，再分别列出旧v5、v6两种起点；三者不是同一次flow。

预筛发生在同网复用、悬空尾段裁剪及形状检查之后，使用合并后的完整候选网络。它检查实际十字交叉到候选及异网真实引脚、折角、分支的现有方形净区；人工切段和临时出口不当作新增真实结构点。普通并行折角不会仅因为离异网小于交叉净区而被拒绝。线端误接、固定出线、穿体、同网连通等仍由后面的完整验收处理，预筛只提前拒绝能明确证明的交叉净区违规。

默认仍为5秒、最多512个候选，沿用四阶段累计25%／50%／75%／100%的时间配额和128／256／384／512的候选上限。器件位置、网表、SA、A*、几何规则、评分权重和恢复链保持原样。结构增强及实验对称仍默认关闭。

## 使用与复现

```powershell
# 10个保存起点串行验证，各自独立5秒，不运行SA和A*
.\.venv\Scripts\python.exe -B .\tools\compare_cross_clearance.py

# 只比较图23的三种保存起点
.\.venv\Scripts\python.exe -B .\tools\compare_cross_clearance.py --cases data23-v5 data23-v6 data23-v7-v6 --out-dir .\output\candidate-clearance-v8\data23-check

# 任意已保存结果：只验收并安全简化，写入独立目录
.\.venv\Scripts\python.exe .\run_flow.py --simplify-placement .\output\7\7-placement.json --out-dir .\output\7-v8
```

对照入口为 `output/candidate-clearance-v8/index.html`，原始记录为同目录的 `comparison.json`。

主组包括图1～7和图23旧v5成品；另有图23的v6成品、v6后又完成v7的10489线长成品两种额外起点。每个起点各自再给v8独立5秒，历史线路和历史预算不同，不能把它们说成同一次flow，或同一份未简化线路的公平版本比较。图1～3原保存结果为v3，图4～7为v4，也分别注明来源。

## 验收与展示

每份成功结果都独立检查原引脚连接、固定出线、同网连通、异网分离、完整几何、最终指标、黑白与彩色SVG同线及独立重绘一致。还验证关闭简化不改线、同版本保存回放稳定、器件位置和物理行列轴不变，以及原网表、原JSON和原主图字节不变。工具通过补丁禁止SA、A*和恢复链被意外调用。

图23用独立诊断SVG将`iref`标红、`net9`标蓝；坐标与正式成品相同，只改变颜色和强调线宽。报告列出两网的实际线长、端点包围盒外线长、向左和向上突出距离、上方水平轨道，以及各简化操作的预筛和完整验收数量。突出包含正常固定出线，只用于定位大圈，不代表所有突出都能删除。

每个接受的修改仍必须保证整图线长、交叉和折角都不增加，并至少缩短线长或减少折角。超时保留最后一份完整验收通过的结果。报告区分预筛拒绝、完整几何拒绝和预算停止，不把未收敛当成无解。

### IREF顶部确实收回的两组结果

从v6成品继续时，`iref`先把左轨从x=-150内收到136，再把顶轨从y=-260收至2。IREF网络3092→1972，向左突出424→138，向上突出416→154；`net9`保持此前内收的y=14及872线长。加上`outp`重接和`net6`局部缩短，整图11206→9943。

从v6后已完成v7的10489线长成品继续时，左轨原本已是x=136，本轮顶轨从y=-260收至2，该条链1158→634，IREF2496→1972；`net10`另缩短12，`outp`另减少一个折角，整图10489→9953。

这两份结果的IREF顶部大圈已经明显收紧，但顶轨仍在端点框上方154单位，左侧仍突出138单位；不能说所有外围线路都已消除。三组图23最后都因5秒截止停止，均未收敛。

### 旧v5起点仍残留两处顶部绕行

旧v5成品只追加本轮独立5秒时，IREF3612→2496，左轨x=-150→136，但IREF顶轨y=-260、`net9`顶轨y=-272仍未改变。该结果不能用另外两组更好的图片替代，也不能据此承诺一次默认flow会达到连续多轮后处理的效果。
