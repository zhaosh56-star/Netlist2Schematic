# 电压源、电流源复用两端模块布局

独立电压源 V、独立电流源 I 现在可以与 R/C/L/D 一起，在有源骨架排好之后按实际端口插入。新网表的默认 `--passive-skeleton auto` 会在候选2、3中使用这项能力；候选1仍是原参照。已有JSON重布、缩线和独立重绘保留保存坐标。

这里复用的是**布局方法**。不会真正短接源，不会修改电气分层、网表节点、正负端、源值或电流箭头。不依据器件编号、文件名、GT坐标或电压源的正负号推断主支路。

单端源及其RLC串并联模块现补充[端部二维找位](passive-modules.md#端部模块二维找位)：原完整插入静态检查通过后，使用剩余局部预算围绕真实端口整体平移。保留原方向、主列和几何规则，中间插入及成对负载族仍走原联合计划；保存JSON不自动摆件。

## 先判断连接关系

| 场景 | 处理 |
| --- | --- |
| 源位于两只有源管的导通端之间，且端口角色唯一 | 建立只用于显示的上下关系，复用主列保护、真实引脚对齐、模块预留空间及插入 |
| 尾源接共同S/E节点 | 把该节点作为附件锚点，优先放在真实接点的中间，并按供电/地侧安排上下 |
| 电压源经唯一R/L/C链接G/B | 源和串链组成一个两端模块，靠近控制端安放；链内每个原节点都保留 |
| 源与无源组成串联、并联或嵌套串并联 | 复用现有模块几何；并联不被误作唯一串联主支路 |
| 只有电源和地、浮空、短接、闭环或无法确定两端模块 | 源保留在原核心中，记录跳过依据，不丢弃器件 |

两端都连有源管时，只有唯一导通宿主及相容的入口/出口证据才能修正显示顺序。G/B控制抽头仍参与绘图、布线和验收，不被当作另一条主干。会引入循环的源关系被拒绝，已有R/L/C主列及显示关系继续保留。没有MOS/BJT的电路沿用原布局路径。

## 执行顺序

1. 用原解析器取得同一份器件和端子数据。
2. 识别可插入的两端源模块。不支持的源变回外部边界，再恢复相邻R/C/L的原计划。
3. 在完整原网表上推导显示关系，原电气层级不改。
4. 从本候选的骨架中取出已确认模块成员，运行原SA、主列整理和串接对齐。
5. 根据真实符号尺寸、引脚方向、halo及标记预留空间，插入模块。
6. 器件、固定出线、供电引线与标记均通过原静态检查；源模块没有特殊避障豁免。
7. 原A*、完整验收、恢复链、候选选择及安全缩线继续执行。

没有增加SA/A*次数、恢复阶段或时间预算。模块插入继续与原局部收尾共享1秒、128次试摆；不完整的模块试案不会作为成功布局输出。归属不明确或空间不足仍可能跳过提案、使用原参照候选或进入原恢复链。

## 代码与保存

- `plugins/passive_skeleton/source_modules.py`：选择可插入源、构造只用于显示的源支路关系。
- `modules.py`、`plan.py`：复用两端串并联树，保存原节点、宿主及控制抽头。
- `candidates.py`、`placement.py`：核心提取、原SA、真实几何插入、公共S/E节点居中及回滚。
- `plugins/layout_shared/branch_levels.py`、`plugins/columns/column_layout.py`：消费源的显示顺序和跨模块主列关系，保护原列计划。
- `common/passive_coordinates.py`：原`local_offset`字段新增V/I白名单，MOS/BJT仍不得使用该二维自由偏移。

JSON的`passive_skeleton.source_layout`记录源布局版本、模块内源、保留在核心的源、跳过原因及源支路证据。原`placement[id].local_offset`继续保存模块的实际偏移；符号位置、真实引脚、障碍、保存恢复和渲染共用同一份坐标。扩距时模块按真实宿主整体平移，不拉散内部成员。旧JSON兼容，资源和源文件哈希仍须符合原规则。
